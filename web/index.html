公式 VOICEVOX CORE を、ブラウザの中の x86-64 エミュレータで動かす

VOICEVOX を移植したのではありません。公式のバイナリをそのまま、1 命令ずつ実行しています。 ゲストは Linux x86-64 のプログラムで、CPU だけが WebAssembly で書かれたソフトウェアです。

VOICEVOX の音声モデルは暗号化されていて、パッチの当たった voicevox_onnxruntime だけが開けます。だから推論エンジンを自前で書き直しても、声は出せません。 この方法はその逆で、公式のランタイムに、公式のやり方で仕事をさせます。 逆コンパイルも抽出もしていません。

ブラウザ → WebAssembly の x86-64 エミュレータ → 本物の ld-linux-x86-64.so.2
  → libvoicevox_core.so → libvoicevox_onnxruntime.so → 音声

    理由は二つ。インタプリタ方式のエミュレータは 1 秒に数千万命令しか実行できません
    （実機は数十億です）。そして CPUID が SSE2 までしか申告しないので、
    ONNX Runtime は一番遅いカーネルを選びます。
    速くするには JIT が要り、それは別のプロジェクトです。
  





出てくる音は本物と同じか



  

    同じです。「あ」を両方で合成して比べると、25132 バイトの WAV のうち
    サンプルの最大差は 3（ピーク 3912 に対して 0.077%）、RMS 差は 0.0078% でした。
    完全一致しないのは、RSQRTPS と RCPPS が定義からして
    近似命令で、実機は 12 ビット程度、このエミュレータは正確に計算するからです
    ——どちらも仕様の範囲内で、聴いて分かる差ではありません。
  





ネイティブから使うなら



  

    同じエミュレータの上に voicevox_core と同じ C API を実装してあります。
    公式の voicevox_core.h の 63 関数を、同じシグネチャ・同じ意味で。
    本家の代わりに voicevox_core.dll をリンクすれば、
    CORE のビルドが存在しないマシンでもそのコードが動きます。
    このページの音声も、その API を通して作られたものです。
  






  音声を利用する場合は VOICEVOX:ずんだもん のクレジット表記が必要です。
  詳しくは 音源利用規約 を参照してください。
